### Refactoring

**You own the contract. The structure changes; the behavior does not.** For "refactor", "rename", "extract", "inline", "dedupe", "restructure", "move this module", "tidy up this area". Distinct from Feature, which adds behavior, and Bug fix, which corrects it.

A refactor that smuggles in a behavior change loses its safety net. If the cleanup reveals a missing feature or a real bug, split it out and ship the structural change first against the pinned contract. A redesign is allowed, but name it and route to Feature.

1. Pin the behavior contract first. Run the **how** skill over the affected subsystem to learn the contract, then write a characterization test, snapshot, or equivalence harness that captures current behavior before any structure moves. The harness makes "refactor" a checkable claim with [**principle-prove-it-works**](../../principle-prove-it-works/SKILL.md). If the area has no coverage, write the pin before touching structure. Type check and lint are not a pin.
2. Name the structure the code is missing per [**principle-model-the-domain**](../../principle-model-the-domain/SKILL.md): a state machine over scattered booleans, a table or registry over spread-out branching, a typed model over repeated shape assumptions, a reducer over ad hoc mutations. Boring code stays when the shape is already clear and local; the reshape must delete branches or invalid states, not add indirection.
3. Name the target shape. State what the module layout, types, and call graph should be if built today with [**principle-foundational-thinking**](../../principle-foundational-thinking/SKILL.md). If the target crosses a function boundary, run the **architect** skill for parallel design exploration of the shape before the move.
4. Subtract before you add. Delete dead weight, collapse one-caller wrappers, drop redundant validators, and remove orphan references before introducing the new shape with [**principle-subtract-before-you-add**](../../principle-subtract-before-you-add/SKILL.md). The smallest change that reaches the target shape ships per [**principle-laziness-protocol**](../../principle-laziness-protocol/SKILL.md). A speculative cleanup that "might help" gets reverted, not left to ride.
5. Move in small behavior-preserving steps, each keeping the pin green. For API reshapes, migrate every caller and delete the old API in the same wave with [**principle-migrate-callers-then-delete-legacy-apis**](../../principle-migrate-callers-then-delete-legacy-apis/SKILL.md). No compatibility shims, no parallel old-and-new paths. Spot-check every rename against the actual files; renames silently miss usages in strings, prose, and back-references. Delegate the mechanical edits to a worker with a unique `task_name` and specific scope: file paths, names being moved, and behavior to hold. Inherit the parent model unless an explicit `model` and `reasoning_effort` override is justified. Review the diff yourself.
6. Prove behavior is unchanged on the real artifact, not "it compiles," with [**principle-prove-it-works**](../../principle-prove-it-works/SKILL.md). For larger reshapes, run an equivalence check: a script that diffs old-vs-new outputs, a recorded baseline replayed against the new code, or a smoke run on the matching surface via the project verification skill. Own the verification yourself; do not trust a delegate's "looks good" summary.
7. Confirm the change earns its place. The success measure is reduced reader load per [**principle-minimize-reader-load**](../../principle-minimize-reader-load/SKILL.md): fewer layers between question and answer, less hidden state, fewer indirections without a second consumer. If the diff does not lower reader load somewhere, revert it.
8. Rebase into small ordered commits that tell the story. A subtraction commit, then the reshape, then any follow-on cleanup, so a single revert undoes one slice. Shape them with [**principle-sequence-verifiable-units**](../../principle-sequence-verifiable-units/SKILL.md), so each behavior-preserving slice stays green before the next.

**Reply:** the structure that changed, the pin you held it against, the equivalence proof, the reader-load delta, what shipped and what got reverted. No new behavior.
