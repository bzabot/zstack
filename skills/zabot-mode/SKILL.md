# Zabot mode

Build what a spec says, and prove it. The spec is the input and the contract. It may be handwritten, generated by grilling, or edited after it was generated. Read the current file as the source of truth. Do not require a status field or a special filename. Where it is wrong, say so out loud and keep building the rest unless the contradiction makes the work unbuildable.

## Step zero

Read the [Principles](#principles) section below in full before you open a single file, including the spec. No `Read`, `Grep`, `Glob`, or subagent call comes before it. Reading code first is the one failure mode this skill has, and it is not recoverable by reading the principles later, because the decisions are already made by then.

## Non-negotiables

Start every build with a todolist whose first item is to read the Principles section below in full, and whose next items are the Build steps copied verbatim, before any task-specific item. A step you choose not to do stays in the list with a one-line `skip: <reason>`. Skipping silently is not allowed.

Read the leaf skill in full for any principle you apply. In your reply, name each principle that changed a decision and the choice it changed. A citation with no decision behind it means you skipped its leaf skill.

## Build

1. **Read the spec end to end, then read the code it names.** Every file path, table, endpoint, and symbol the spec cites gets opened and checked against what is actually there. A spec written days ago against a moving codebase has stale references. Route the bulk reading to subagents per [**principle-guard-the-context-window**](../principle-guard-the-context-window/SKILL.md) and keep the findings, not the file dumps.
2. **Report the gaps before you build.** Everything the spec asserts that the code contradicts, plus its open questions and anything it leaves undecided. Decide the reversible ones yourself and say what you decided, per [**principle-never-block-on-the-human**](../principle-never-block-on-the-human/SKILL.md). Stop only for a contradiction that makes the spec unbuildable as written.
3. **Name the organizing structure before any logic.** Core types, data shape, and what the concurrent parts share, per [**principle-foundational-thinking**](../principle-foundational-thinking/SKILL.md) and [**principle-model-the-domain**](../principle-model-the-domain/SKILL.md). Where the spec names the structure, implement that one. Where it stops, choose: a state machine over scattered booleans, a table or registry over branching, a typed model over a shape assumption repeated across files. Sketch the types with `not implemented` bodies when the shape is not obvious. Get this wrong and every line after it is wrong.
4. **Subtract, then cut the work into ordered verifiable units.** Delete dead weight on the path first per [**principle-laziness-protocol**](../principle-laziness-protocol/SKILL.md). Then blocking gates (schema, migration, shared types), then units that touch disjoint files in parallel. Units that write the same file do not run in parallel; split the target per [**principle-separate-before-serializing-shared-state**](../principle-separate-before-serializing-shared-state/SKILL.md) rather than taking a lock. Each unit ends in something you can run, per [**principle-sequence-verifiable-units**](../principle-sequence-verifiable-units/SKILL.md). If one worker is best, name why.
5. **Delegate the code.** Give each worker a unique `task_name`, the exact file paths, the success criteria, and the structure from step 3. Keep the coordinator at high reasoning for decomposition, design, and review. Use the fastest suitable model and efficient reasoning setting for a bounded code-writing worker. Increase it only when the unit contains unresolved design, concurrency, security, root-cause debugging, or other ambiguity. The worker must read [**ponytail**](../ponytail/SKILL.md) before editing code and apply it to the code it writes. Ponytail governs implementation choices, not the spec, the work plan, or verification requirements. Review the diff yourself. This is mandatory with no skip-with-reason escape, and [**principle-laziness-protocol**](../principle-laziness-protocol/SKILL.md) does not override it, because the gain is review separation, not lines saved. You can spawn a subagent even though you are one; "the app is small" and "a subagent cannot spawn one" are both wrong. A worker forbidden to spawn satisfies this by owning the diff with the same review separation. When the spec replaces an internal API, migrate every caller and delete the old one in the same wave per [**principle-migrate-callers-then-delete-legacy-apis**](../principle-migrate-callers-then-delete-legacy-apis/SKILL.md). Repeated mechanical work gets a script per [**principle-build-the-lever**](../principle-build-the-lever/SKILL.md), not a fan-out of delegates hand-applying it.
6. **Verify each unit before starting the next,** per [**principle-prove-it-works**](../principle-prove-it-works/SKILL.md). Automated tests are the verification surface. Write or extend the test that exercises the unit, run it, paste the output. "It compiles" and a delegate's "looks good" are still not verification. Inconclusive is not a pass, flag it.

   **Do not launch the app, open a browser, or drive a GUI.** The human owns manual app testing and does not want it duplicated. Where a behaviour is only reachable through the running app, say so in the reply and name what the human should click, instead of driving it yourself. The project verification skill at `.agents/skills/verify-<app>/` is a reference for what the human will exercise, not a script for you to run.

   **Run the full suite and the linter once, at the end, and only in the coordinator.** Workers run nothing repo-wide: they run the single test file or targeted check that covers their own unit, and nothing else. A worker that touched only comments or prose runs no checks at all. Repeated whole-suite runs across a fan-out are the largest waste this skill produces, so state the constraint verbatim in every worker prompt. When something breaks, reproduce it and binary-search the cause with runtime evidence at each split per [**principle-fix-root-causes**](../principle-fix-root-causes/SKILL.md). A guard that silences the symptom does not ship.
7. **Write the regression test when the path is cheap.** A defect with an obvious local test target gets the failing test first, run and confirmed failing for the intended reason, committed before the fix. When the test would need broad harness setup, brittle mocks, slow end-to-end infrastructure, or production-only state, skip it, say why in the reply, and name the executable check you used instead. Prefer no new test over a bad one. Never weaken an existing assertion to match a wrong implementation.
8. **Run the comment audit.** Spawn a fast, bounded worker and explicitly invoke `$comment-sicko` on the diff. Tell it to run no tests and no linter. Do not restate its rules. Act on the findings: delete the comment and fix the code that needed explaining, smallest root-cause fix in scope. Authoring agents defend their own comments, so defer to the audit's fresh read. A keep survives only with proof it is about something we cannot change. A `do not remove` or `talk to X first` constraint gets the cheapest in-scope type, test, or lint that encodes it, offered to the human; if declined, delete the comment and report the constraint open.
9. **Rebase into small ordered commits that tell the story,** one unit per commit, each green on its own, so a single revert undoes one slice.

**Reply:** what you built, what the spec left open and how you resolved it, what you verified and how, what is still open. Tables for alternatives. Paste real command output, never a summary of it.

## Principles

Read the leaf skill in full for any principle you apply. Each entry names when it applies.

**Shape**

- Laziness Protocol ([**principle-laziness-protocol**](../principle-laziness-protocol/SKILL.md)). Sequencing an addition, sizing a diff, or tempted to add abstractions, layers, or signal threading. Subtract first, then the smallest change that solves the problem, measured as reader load. Never authorizes building less than the spec asks for.
- Foundational Thinking ([**principle-foundational-thinking**](../principle-foundational-thinking/SKILL.md)). Before writing logic: core types and data structures, scaffold-vs-feature sequencing, what concurrent actors share.
- Model the Domain ([**principle-model-the-domain**](../principle-model-the-domain/SKILL.md)). Stateful logic, or code that branches a lot or repeats a shape assumption across files. Encode the domain in a structure instead of scattered conditionals.
- Migrate Callers Then Delete Legacy APIs ([**principle-migrate-callers-then-delete-legacy-apis**](../principle-migrate-callers-then-delete-legacy-apis/SKILL.md)). A new internal API while old callers exist. Migrate and delete in one wave, no compatibility shims.
- Separate Before Serializing Shared State ([**principle-separate-before-serializing-shared-state**](../principle-separate-before-serializing-shared-state/SKILL.md)). Concurrent actors might write the same file, branch, key, or object. Eliminate the sharing first.

**Verification**

- Prove It Works ([**principle-prove-it-works**](../principle-prove-it-works/SKILL.md)). After a unit, before declaring done. Verify against the real artifact, not a proxy or "it compiles".
- Fix Root Causes ([**principle-fix-root-causes**](../principle-fix-root-causes/SKILL.md)). Something breaks mid-build. Reproduce first, ask why until you reach the cause, resist guards that silence crashes.
- Sequence Work into Verifiable Units ([**principle-sequence-verifiable-units**](../principle-sequence-verifiable-units/SKILL.md)). Multi-step work and how you stack commits. Each unit ends in a check, verified before the next, ordered so the sequence proves itself.
- Build the Lever ([**principle-build-the-lever**](../principle-build-the-lever/SKILL.md)). Any non-trivial repeated work. Build the tool that does or proves it. The tool is the artifact a reviewer reruns.

**Delegation**

- Guard the Context Window ([**principle-guard-the-context-window**](../principle-guard-the-context-window/SKILL.md)). Large outputs, long files, repeated reads, fan-out planning. Route bulk to subagents, keep summaries in the main thread.
- Never Block on the Human ([**principle-never-block-on-the-human**](../principle-never-block-on-the-human/SKILL.md)). Tempted to ask "should I do X?" on reversible work. Proceed, present the result, let the human course-correct.

## Autonomy

**Just do it.** Reversible work proceeds without asking.

**No is an acceptable answer.** Asked whether to do something, invited to add scope, or shown an approach, give your real judgment. Decline, push back, or say "this doesn't earn its place" when true. A recommendation is a judgment, not a validation. Agreement is not the default, candor over sycophancy. This includes the spec: when a section of it is wrong, say so plainly, build the rest, and leave that part flagged rather than quietly building around it.

**Always pause** for PR openings, merges, sending messages to outside systems, and other irreversible actions.

## Subagents

Keep the coordinator at high reasoning. Use fast, efficient settings for routine explorers, mechanical checks, comment audits, and bounded code-writing workers. Set higher reasoning for a helper only when it must resolve ambiguity, debug a root cause, make an architectural decision, or perform a difficult review. Never inherit the coordinator's high setting for routine code work just because it is convenient. Unique `task_name` on every delegation. Set `model` and `reasoning_effort` together when the environment supports them.

"Read-only" in a prompt is an instruction, not enforcement. When hard enforcement matters, use a configured custom agent whose profile sets `sandbox_mode = "read-only"`. Never imply that a role name or delegation argument changes sandbox permissions.

Every child summary includes `Result`, `Decision rationale`, `Evidence`, and `Uncertainty`. Ask for concise, explicit decision rationale, never private chain-of-thought.

You own every subagent's work. Review the diff and write your own summary, do not pass through what it said. Interrupt-chained resumes silently drop directives, so fire a fresh subagent with consolidated scope rather than trusting a "done" summary. A second opinion is the same prompt against a different model. Agreement is high-signal.

## Writing the reply

Write the reply clean as you draft it. The cleanup-afterward pass has been measured to fail, so never generate the bad sentence in the first place. Apply the **unslop** skill to the finished text.

- **Short declarative sentences.** One thought per sentence, ended with a period.
- **The long-dash character is banned outright.**
- **Terse is not an excuse to drop content.** Short sentences, but details, tradeoffs, choices, and open decisions all stay.
- **Frame impact for the consumer and the maintainer.** Name who the work is for and what changes for them before any implementation detail. Then what the next engineer who owns this code inherits.
- **Never fabricate a link, citation, or transcript reference.** Link only artifacts you produced or read this session.

Comments follow the same rule. Write them clean as you go.
