How the Express router dispatches a request

One array, one cursor, and a function called next. Everything else in the subsystem exists to keep that loop honest about paths, params, methods and errors.

pillarjs/router v2.2.0 · index.js, lib/layer.js, lib/route.js · 1,237 lines · MIT

This is the routing engine Express 5 mounts, published on its own. It is small enough to read in an afternoon and dense enough that most of it is not obvious. This page follows a single request through the three files and stops at each mechanism that is doing something a reader would not guess: arity as a protocol, string values used as control-flow signals, and a request object whose url is temporarily rewritten and then put back.

1. Background

The smallest mental model

A router is a function with the same shape as the handlers it contains:

const Router = require('router');
const router = Router();

router.use(logger);                       // middleware, any method, prefix match
router.get('/users/:id', sendUser);        // route, GET only, exact match

http.createServer(function (req, res) {
  router(req, res, function (err) {        // the router is just a handler
    res.statusCode = err ? 500 : 404;
    res.end();
  });
});

That self-similarity is the point of the design: because a router is a handler, a router can be used inside another router, and mounting composes without any special case.

function Router (options) {
  if (!(this instanceof Router)) {
    return new Router(options)
  }

  function router (req, res, next) {
    router.handle(req, res, next)
  }

  Object.setPrototypeOf(router, this)      // a callable with Router's methods
  router.stack = []
  return router
}

Router.prototype = function () {}          // so the prototype is callable too

The three objects

Router — index.js

Owns stack, an ordered array of Layers, plus the dispatch loop, the param callback registry, and the mounting rules. 748 lines, and about half of them are handle and its helpers.

Layer — lib/layer.js

One path matcher plus one handler. Knows how to test a pathname, extract params, and invoke its function in the request channel or the error channel. 247 lines.

Route — lib/route.js

One path, many methods. Holds its own stack of Layers tagged with an HTTP method and dispatches within itself. 242 lines.

Definition

Layer. The uniform element of every stack in the subsystem. Two flavours exist, distinguished only by whether layer.route is set. A middleware layer (from use) has route === undefined and matches path prefixes. A route layer (from route or a verb shorthand) has a Route attached and matches the whole path. Because both are Layers, the dispatch loop iterates one array with one rule and branches only where the difference truly matters.

2. Intuition

Dispatch is a paused for-loop

The core idea: hold an index into the stack, invoke the next matching layer, and stop. Resuming is somebody else's job, and that somebody is the handler, when it calls next().

handle(req, res, done)
  idx = 0
  next()

next(err)
  restore anything the previous layer's mount rewrote
  if err === 'router'                → done(null)
  if idx >= stack.length             → done(err)
  advance idx until a layer matches this pathname (and method, for routes)
  if none                            → done(err)
  run this layer's param callbacks, then hand it (req, res, next)

A handler that never calls next and never answers leaves the request hanging forever; there is no timeout in this subsystem. A handler that calls next twice re-enters the loop twice from wherever the cursor now is, which is why double-next bugs produce such strange symptoms.

Errors ride the same channel, sorted by arity

There is no separate error stack. An error is a value passed to next, and it changes which layers are willing to run:

Handlernext() — no errornext(err) — error pending
(req, res, next)runsskipped, error passed on
(err, req, res, next)skippedruns
a route layerruns if the method matchesnever matches

The test is fn.length. Function arity is the entire type system here, which is worth internalising because it explains a whole class of confusing bugs: give an error handler a default parameter or a rest parameter and its length drops below 4, and it silently stops being an error handler.

Two strings mean something

next('route')

Skip the rest of this route's handlers and continue the router's stack. Meaningful only inside a route.

next('router')

Leave this router entirely and hand back to its caller with no error, skipping every remaining layer.

Mounting works by lying to the handler about the URL

A handler mounted at /admin should be able to route as if it owned the origin. So before invoking a middleware layer, the router slices the matched prefix off req.url and appends it to req.baseUrl; on the way back out, next puts both back.

Outside the mount

req.url         '/admin/users/7'
req.baseUrl     ''
req.originalUrl '/admin/users/7'

Inside use('/admin', sub)

req.url         '/users/7'
req.baseUrl     '/admin'
req.originalUrl '/admin/users/7'

originalUrl is set once and never rewritten, so it is the only field that is meaningful for logging.

3. Code

3.1 Building the stack — use, route, and the verbs

use starts by working out whether its first argument is a path, because the path is optional:

index.js

Router.prototype.use = function use (handler) {
  let offset = 0
  let path = '/'

  if (typeof handler !== 'function') {
    let arg = handler
    while (Array.isArray(arg) && arg.length !== 0) {
      arg = arg[0]                     // dig through router.use([[fn]])
    }
    if (typeof arg !== 'function') {
      offset = 1
      path = handler
    }
  }

  const callbacks = flatten.call(slice.call(arguments, offset), Infinity)
  // ... each must be a function, or TypeError

  const layer = new Layer(path, {
    sensitive: this.caseSensitive,
    strict: false,
    end: false                          // prefix match
  }, fn)

  layer.route = undefined               // marks this as middleware
  this.stack.push(layer)

end: false is the prefix-match flag and strict: false is hard-coded here: mounted middleware ignores trailing-slash strictness even when the router is strict, because a mount point is a prefix and not an endpoint.

route builds the other flavour. Note that the Layer's handler is a closure that delegates into the Route, which is how a nested stack hangs off a flat one:

index.js

Router.prototype.route = function route (path) {
  const route = new Route(path)

  const layer = new Layer(path, {
    sensitive: this.caseSensitive,
    strict: this.strict,
    end: true                           // whole-path match
  }, handle)

  function handle (req, res, next) {
    route.dispatch(req, res, next)
  }

  layer.route = route
  this.stack.push(layer)
  return route
}

methods.concat('all').forEach(function (method) {
  Router.prototype[method] = function (path) {
    const route = this.route(path)
    route[method].apply(route, slice.call(arguments, 1))
    return this
  }
})

So router.get(p, fn) is sugar for router.route(p).get(fn), and every verb call creates a new route and a new layer. Two router.get('/x', ...) calls produce two independent routes in the stack, not one route with two handlers.

3.2 Matching — Layer.match

A Layer compiles its path once at construction into an array of matcher functions, one per path when given an array:

lib/layer.js

this.slash = path === '/' && opts.end === false
// ...
return pathRegexp.match((opts.strict ? _path : loosen(_path)), {
  sensitive: opts.sensitive,
  end: opts.end,
  trailing: !opts.strict,
  decode: decodeParam
})
// ...
this.matchers = Array.isArray(path) ? path.map(matcher) : [matcher(path)]

loosen strips trailing slashes from a non-strict path. slash is the pathless-use fast path, and it short-circuits everything:

lib/layer.js

Layer.prototype.match = function match (path) {
  let match

  if (path != null) {
    if (this.slash) {                   // use(fn): matches anything
      this.params = {}
      this.path = ''
      return true
    }

    let i = 0
    while (!match && i < this.matchers.length) {
      match = this.matchers[i](path)
      i++
    }
  }

  if (!match) {
    this.params = undefined
    this.path = undefined
    return false
  }

  this.params = match.params
  this.path = match.path
  this.keys = Object.keys(match.params)
  return true
}

this.path = '' for the slash case matters later: it makes trimPrefix a no-op, so pathless middleware never rewrites the URL.

Edge case

A malformed param is a 400, thrown from matching. decodeParam runs decodeURIComponent and, on a URIError, rewrites the message and attaches err.status = 400 before rethrowing. So /users/%A fails inside layer.match, not inside a handler. That is why the dispatch loop wraps matching:

function matchLayer (layer, path) {
  try {
    return layer.match(path)
  } catch (err) {
    return err                          // not a boolean: becomes layerError
  }
}

Returning a non-boolean is the signal. The loop keeps that error aside and keeps scanning, so a later matching layer or an error handler still gets a turn.

3.3 Dispatch setup — what handle arranges before looping

index.js

Router.prototype.handle = function handle (req, res, callback) {
  if (!callback) {
    throw new TypeError('argument callback is required')
  }

  let idx = 0
  const protohost = getProtohost(req.url) || ''
  let removed = ''
  let slashAdded = false
  let sync = 0
  const paramcalled = {}

  const stack = this.stack
  const parentParams = req.params
  const parentUrl = req.baseUrl || ''
  let done = restore(callback, req, 'baseUrl', 'next', 'params')

  req.next = next

  if (req.method === 'OPTIONS') {
    methods = []
    done = wrap(done, generateOptionsResponder(res, methods))
  }

  req.baseUrl = parentUrl
  req.originalUrl = req.originalUrl || req.url

  next()

Four of these deserve a name:

  • restore captures req.baseUrl, req.next and req.params now and puts them back when done is finally called. A nested router therefore cannot leak its view of the request to its parent, however it exits.
  • protohost is the scheme://host prefix of an absolute-form request target, which a proxy can send. All URL slicing is offset past it so rewriting never eats the host.
  • paramcalled memoises param callbacks for the life of one dispatch, so a value is not re-loaded when several layers capture the same key.
  • sync counts consecutive synchronous next calls. It is the stack-depth guard, below.

3.4 The loop — next

index.js

function next (err) {
  let layerError = err === 'route' ? null : err

  if (slashAdded) {                       // undo the previous layer's mount
    req.url = req.url.slice(1)
    slashAdded = false
  }

  if (removed.length !== 0) {
    req.baseUrl = parentUrl
    req.url = protohost + removed + req.url.slice(protohost.length)
    removed = ''
  }

  if (layerError === 'router') {
    setImmediate(done, null)
    return
  }

  if (idx >= stack.length) {
    setImmediate(done, layerError)
    return
  }

  if (++sync > 100) {
    return setImmediate(next, err)
  }

  const path = getPathname(req)
  if (path == null) {
    return done(layerError)
  }

The first thing next does is undo, not advance. Mount rewriting is per-layer, so the URL is restored on every re-entry before the next candidate is considered. At the top, next('route') is neutralised into "no error" for a router: the signal is meant for a Route's loop, and reaching the router means it has done its job.

Why sync > 100 exists

Middleware that calls next() synchronously grows the JS stack: next to handler to next to handler. A stack of a few hundred purely synchronous layers would overflow. After 100 consecutive synchronous hops the loop trampolines through setImmediate, unwinding to the event loop and continuing on a fresh stack. The counter is reset to 0 after a layer is actually invoked, so it measures a run of synchronous hops rather than total layers, and an async handler anywhere in the chain costs nothing.

Then the scan, which is where the two layer flavours diverge:

index.js

while (match !== true && idx < stack.length) {
  layer = stack[idx++]
  match = matchLayer(layer, path)
  route = layer.route

  if (typeof match !== 'boolean') {
    layerError = layerError || match      // a decode error; keep the first
  }

  if (match !== true) continue
  if (!route) continue                    // middleware: path match is enough

  if (layerError) {
    match = false                         // routes never run with an error pending
    continue
  }

  const method = req.method
  const hasMethod = route._handlesMethod(method)

  if (!hasMethod && method === 'OPTIONS' && methods) {
    methods.push.apply(methods, route._methods())   // collect for the Allow header
  }

  if (!hasMethod && method !== 'HEAD') {
    match = false
  }
}

if (match !== true) {
  return done(layerError)
}

Three rules live in that loop. A route with a pending error is not a candidate, which is what makes error handling flow past your route handlers to your error middleware. A path-matching route whose method is wrong is skipped, but on the way past it contributes its verbs to the automatic OPTIONS answer. And HEAD is not skipped even without a head handler, because Route will fall back to get.

Having chosen a layer, the router snapshots its params and defers to the param callbacks:

index.js

req.params = self.mergeParams
  ? mergeParams(layer.params, parentParams)
  : layer.params
const layerPath = layer.path

processParams(self.params, layer, paramcalled, req, res, function (err) {
  if (err) {
    next(layerError || err)
  } else if (route) {
    layer.handleRequest(req, res, next)   // into Route.dispatch
  } else {
    trimPrefix(layer, layerError, layerPath, path)
  }

  sync = 0
})

next(layerError || err) prefers the older error: an error already travelling is not replaced by one raised while loading params for the layer that was going to handle it.

3.5 processParams — pre-conditions per captured key

router.param('user_id', fn) registers a callback that runs before any layer whose path captured user_id. The implementation is two mutually recursive functions over two cursors, one across keys and one across that key's callbacks:

index.js

function param (err) {
  if (err) return done(err)
  if (i >= keys.length) return done()

  paramIndex = 0
  key = keys[i++]
  paramVal = req.params[key]
  paramCallbacks = params[key]
  paramCalled = called[key]

  if (paramVal === undefined || !paramCallbacks) return param()

  if (paramCalled && (paramCalled.match === paramVal ||
    (paramCalled.error && paramCalled.error !== 'route'))) {
    req.params[key] = paramCalled.value    // reuse the earlier load
    return param(paramCalled.error)
  }

  called[key] = paramCalled = {error: null, match: paramVal, value: paramVal}
  paramCallback()
}

The memo is keyed by name and validated against the value, so /users/7/posts/9 hitting two layers that both capture id loads once per distinct value. A remembered error is also replayed, so a failed load does not get retried per layer; 'route' is excluded because it is a control signal rather than a failure.

paramCallback invokes each callback as fn(req, res, paramCallback, paramVal, key), catching synchronous throws and attaching to a returned promise's rejection. It also writes paramCalled.value = req.params[key] on each hop, which is what lets a callback replace the raw string with a loaded object and have that survive into the memo.

3.6 trimPrefix — the mount rewrite

index.js

function trimPrefix (layer, layerError, layerPath, path) {
  if (layerPath.length !== 0) {
    if (layerPath !== path.substring(0, layerPath.length)) {
      return next(layerError)
    }

    const c = path[layerPath.length]
    if (c && c !== '/') {                  // /admin must not match /administrator
      return next(layerError)
    }

    removed = layerPath
    req.url = protohost + req.url.slice(protohost.length + removed.length)

    if (!protohost && req.url[0] !== '/') {
      req.url = '/' + req.url
      slashAdded = true
    }

    req.baseUrl = parentUrl + (removed[removed.length - 1] === '/'
      ? removed.substring(0, removed.length - 1)
      : removed)
  }

  if (layerError) {
    layer.handleError(layerError, req, res, next)
  } else {
    layer.handleRequest(req, res, next)
  }
}

The boundary check is the part worth remembering: a prefix match must end at a path separator, so use('/admin', …) does not capture /administrator. The slashAdded flag records that a synthetic leading slash was inserted, because use('/admin') handling /admin exactly leaves an empty URL, and a handler expects at least '/'. baseUrl is assembled without a trailing slash so nested mounts concatenate cleanly.

This is also the only place a middleware layer's error channel is entered, and the two branches are the same call in different channels, which is where lib/layer.js takes over:

lib/layer.js

Layer.prototype.handleRequest = function handleRequest (req, res, next) {
  const fn = this.handle

  if (fn.length > 3) {
    return next()                          // an error handler: not our turn
  }

  try {
    const ret = fn(req, res, next)

    if (isPromise(ret)) {
      ret.then(null, function (error) {
        next(error || new Error('Rejected promise'))
      })
    }
  } catch (err) {
    next(err)
  }
}

handleError is the mirror image: it bails with next(error) unless fn.length === 4, then calls fn(error, req, res, next) with the same throw and rejection plumbing. A rejected handler promise becomes next(err), and a rejection with a falsy reason still produces an error object rather than a silent stall. A resolved promise is ignored: returning normally is not answering the request.

3.7 Route.dispatch — the inner loop

lib/route.js

Route.prototype.dispatch = function dispatch (req, res, done) {
  let idx = 0
  const stack = this.stack
  let sync = 0

  if (stack.length === 0) return done()

  let method = typeof req.method === 'string' ? req.method.toLowerCase() : req.method
  if (method === 'head' && !this.methods.head) {
    method = 'get'                         // automatic HEAD
  }

  req.route = this
  next()

  function next (err) {
    if (err && err === 'route')  return done()     // skip the rest of this route
    if (err && err === 'router') return done(err)  // let the router see it
    if (idx >= stack.length)     return done(err)
    if (++sync > 100)            return setImmediate(next, err)

    let layer, match
    while (match !== true && idx < stack.length) {
      layer = stack[idx++]
      match = !layer.method || layer.method === method   // undefined = .all
    }

    if (match !== true) return done(err)

    if (err) {
      layer.handleError(err, req, res, next)
    } else {
      layer.handleRequest(req, res, next)
    }

    sync = 0
  }
}

Same shape as the router's loop, with three simplifications: no path matching, since the route's own layers are all built with path '/' and are selected by method alone; no URL rewriting; and the two signal strings are handled in the opposite direction. 'route' is consumed here and exits cleanly to the router, while 'router' is forwarded to done so the enclosing router can act on it.

Handlers are added by the verb methods, which flatten their arguments, validate every one, and tag each Layer with its method. all tags with undefined and sets methods._all:

lib/route.js

const layer = Layer('/', {}, fn)
layer.method = method            // or undefined, for .all
this.methods[method] = true      // or this.methods._all = true
this.stack.push(layer)

3.8 The automatic OPTIONS response

Nothing in the loop answers OPTIONS. Instead done is wrapped, so the fallback runs only if the whole stack declined to respond:

index.js

function generateOptionsResponder (res, methods) {
  return function onDone (fn, err) {
    if (err || methods.length === 0) {
      return fn(err)                       // real error, or nothing to advertise
    }
    trySendOptionsResponse(res, methods, fn)
  }
}

The methods array closed over here is the same one the scan pushed into for every path-matching route with the wrong method. sendOptionsResponse dedupes and sorts it, then sets Allow, Content-Length, Content-Type: text/plain and X-Content-Type-Options: nosniff. A throw while responding is routed to next rather than escaping, via trySendOptionsResponse.

Note the asymmetry this creates: only routes contribute to Allow. Middleware registered with use declares no methods, so a use-based endpoint is invisible to OPTIONS, which the source calls out in the comment above use.

3.9 mergeParams — the awkward one

With mergeParams: true, a child router's params are merged over its parent's. Named keys are a plain Object.assign. Numeric keys, which come from unnamed regexp capture groups, cannot be: parent 0 and child 0 are different captures and both must survive.

index.js

if (!(0 in params) || !(0 in parent)) {
  return Object.assign(obj, params)      // no numeric collision possible
}

let i = 0, o = 0
while (i in params) i++                  // count child's numeric keys
while (o in parent) o++                  // count parent's

for (i--; i >= 0; i--) {
  params[i + o] = params[i]              // shift child's up past parent's
  if (i < o) delete params[i]
}

return Object.assign(obj, params)

The child's numeric keys are shifted up by the parent's count, walking downward so no write clobbers an unread slot. The result is parent captures at 0..o-1 and child captures after them. It mutates the params object it was handed, which is layer.params, and that is tolerable only because a Layer's params are rebuilt on every match.

3.10 What the subsystem does not do

  • No timeouts. A handler that neither responds nor calls next hangs the request; the loop has no way to detect it.
  • No double-next protection. Calling next twice runs the remaining stack twice from the current cursor.
  • No final response. Falling off the end calls done(err). Sending 404 or 500 belongs to whoever mounted the router.
  • Arity is unchecked at registration. A five-argument handler is accepted and then skipped by both channels forever, silently.
